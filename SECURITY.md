# Security policy

## Private reporting

Report a suspected vulnerability through the repository's [private security-advisory form](https://github.com/Syntax-Circus/cmsify/security/advisories/new). Do not put vulnerabilities, reproduction data, logs, tokens, connection strings, encrypted key material, or other secrets in a public issue, discussion, pull request, or commit.

The repository administrator must verify that GitHub private advisories are enabled before relying on this route. If it is unavailable, do not disclose the report publicly; ask a maintainer through an already-established private channel to enable the advisory route. This repository does not publish an unverified security email address.

## Supported versions and response targets

The current stable major release line is supported until an end-of-support notice says otherwise. Before stable v1 is released, there is no released Cmsify version with a support commitment. For a private report, maintainers target an acknowledgement within 3 business days, an initial assessment within 10 business days, and a status update at least every 10 business days while it remains open. These are response targets, not a claim that a hosted support service is currently staffed.

## Coordinated disclosure

Keep the report private while maintainers assess impact, prepare a fix, and coordinate a disclosure date with the reporter. A public advisory, release notes, or credit is published only with the reporter's agreement where practical and after affected users have a reasonable upgrade path. Do not exploit a vulnerability beyond the minimum needed to demonstrate it.
